What this system is

A document intelligence system that ingests past RFI Excel files — each with a different schema — builds a searchable corpus of Q&A pairs, and drafts answers to new client RFIs with full source provenance. The retrieval architecture is the product; the draft answer is the output.

Design principles

Nine load-bearing decisions. Each one is a concise statement plus the reasoning that would survive a challenge.

1. Discover schema; never assume it. Clients set the RFI format, not us. Every assumption about column positions, header rows, or sheet layout will eventually be wrong. The profiler discovers structure at profile time and persists the discovery to a config file. Runtime paths (ingest, query) treat the config as ground truth. Discovery cost is one-time; the payoff compounds across every new file format that arrives.
2. Stack layers with complementary failure modes. The schema profiler has three layers: heuristic (deterministic, cheap), LLM (phrasing-aware, non-deterministic), and validator (constraint enforcement). Each layer catches what the one below it misses. Adding a layer that fails on the same inputs as an existing one adds no robustness; adding one that fails on disjoint inputs does. The human is the fourth layer — for semantic correctness no machine can verify.
3. Validate before showing humans. Reserve human attention for semantic judgements. The validator runs between the LLM and the human. A broken mapping (duplicate roles, invented role names) never reaches the approval screen. Human attention is reserved for the question the validator cannot answer: "Is column B actually the question, given what I know about this client?" Conflating deterministic checks with human review erodes trust in the gate.
4. Measure retrieval; don't commit to an ideology. Hybrid retrieval was the spec's default recommendation. The 36-configuration eval overturned it: semantic outperformed hybrid on this corpus. The right retrieval architecture is empirical, not theoretical — it depends on corpus size, query distribution, and terminology density. The eval ran 36 configurations against a ground-truth dataset before any production recommendation was made. Three of four spec predictions were wrong.
5. Distinguish hallucination refusals from retrieval gaps. Both produce "I cannot find this in our corpus." They mean opposite things. Hallucination refusal = system working correctly. Retrieval gap = system failing. A single refusal rate metric conflates them: a retrieval failure looks like correct grounding. The eval tracks them separately. A high hallucination refusal rate is good; a high retrieval gap rate is a bug to fix.
6. Cross-tenant content leakage needs its own design and eval dimension. Faithfulness, relevance, and completeness metrics cannot catch an answer that names a past client verbatim. The answer is faithful to the retrieved context — the judge scores it at 5.0 — but the client name in the context shouldn't appear in the output for a different client. This is a safety concern that quality metrics are blind to by construction. It needs a prompt-level guard, a post-generation redaction pass, and an eval metric that scores cross-client name occurrence explicitly.
7. The UI participates in the CLI's persistence model; it does not replace it. The approve endpoint writes config_rfi_*.json to repo root — the same file the CLI reads. The approve endpoint copies the uploaded file to data/ — the same directory the CLI loader reads from. Both update the checkpoint file. A session started via the UI is resumable from the CLI without any migration. Designing the persistence contract first and deriving both interfaces from it is what makes this work. A UI that adds a new database instead of participating in the existing contract creates migration debt the first time a third interface appears.
8. Deterministic where the content is a fact; AI judgment only where it adds value. Label-match header detection is deterministic — if a cell contains "Question", that cell is the header. The LLM runs only when the heuristic finds no winner. The hallucination guard is a fixed string comparison — refused answers are flagged without asking the model to judge itself. The client-name scan is a regex pass over known config values — no AI involved. AI is reserved for: schema mapping (phrasing inference from samples), semantic retrieval (vector similarity), answer generation (synthesis from context), and reranking (relevance scoring). Everything else is deterministic.
9. Signal upgrade paths in the original decision; execute them when the trigger fires. The session cleanup started as a startup-only sweep. The original design noted: "if sessions accumulate in practice (long-running deployment + heavy daily use), promote to an asyncio background task." When the home-server deployment removed the daily-restart assumption, the upgrade was a 30-line patch to the exact location the original decision indicated. The general principle: when picking the simpler shape, document the condition that would require the complex shape and the exact form the upgrade takes. Future-you doesn't re-derive the architecture; they check the trigger and execute the named upgrade.
